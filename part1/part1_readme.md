# 개미수열 n번째 항 가운데 두 자리 수 출력

## 문제 정의
### 주어진 문제
- 항을 입력하면 그 항의 개미수열 값을 구함
- 그 값의 가운데 숫자 2개를 최종 출력
### 주어진 조건
- 입력 데이터 범위는 3 초과 100 미만
- 언어, 라이브러리 사용은 자유
- 시간복잡도, 공간복잡도 효율성은 일단 최대한 고려해야함(평가에 반영)

## 해결방법 구상
### 초기
- 개미수열을 검색해보니 [위키백과](https://ko.wikipedia.org/wiki/%EC%9D%BD%EA%B3%A0_%EB%A7%90%ED%95%98%EA%B8%B0_%EC%88%98%EC%97%B4)에 OEIS(온라인 정수열 사전)언급이 있음
- 이걸 활용하면 효율성을 챙길 수 있을 것이라 판단
- 파이썬 라이브러리 중 oeis 라이브러리가 있음
- 하지만 OEIS에 저장된 부분만 나오는 형식
- 3초과 100미만 조건 불충분

### 최종 해결방법 구상
- 개미수열에는 수학적인 공식이 없음
- 방법은 반복문을 통해 계속 구해나가는 방법 밖에 없다고 판단함

## 문제 풀이
- 우선 항을 입력하면 1부터 해당 항까지 반복문 실행
- 개미수열 첫번째 항은 1이니까 시작값을 "1"로 둠(여기서 이 값은 문자열 타입)
- 계산된 각 항 개미수열 값은 리스트에 계속 append
- 최종 개미수열 값은 리스트의 맨 마지막 값
- 개미수열 값을 구한 후 가운데 두 자리 숫자 출력
    - 여기선 anchor를 개미수열 값의 길이 // 2 로 둠
    - 컴퓨터는 0부터라는걸 이용하면 가운데 두자리수는 무조건 anchor-1번째와 anchor번째 숫자
- 개미수열 값은 첫번째 항 제외하고는 무조건 짝수. 그리고 같은 숫자 4개가 연속되는 경우는 없음. 그래서 길이가 홀수인 경우와 같은 숫자 4개가 연속되는 경우는 고려하지 않음
- 마지막 메인 함수에서 범위를 벗어나는 값을 입력한 경우 ValueError가 나오게 설정

## 함수 설명
- Consecutive.find_consecutive_groupby : 입력값은 그 전 항의 개미수열 값(문자열 타입). 연속된 같은 숫자를 하나의 문자열로 묶음. 그 문자열들로 구성된 리스트를 반환.
    - 특이사항 : 정규표현식으로 구현한 것과 itertools.groupby로 구현한 것 2개가 있음. groupby로 구현한 것이 연속된 숫자가 없는 경우를 대응 가능해서 groupby 버전 사용.
- FormatNumber.format_number : 입력값은 find_consecutive_groupby 결과 리스트
    - 개미수열 값처럼 나오게 하는 함수
    - 리스트 안의 값들을 반복하면서
        - 각 문자열 길이와 문자열 첫번째 글자를 하나의 문자열로 합침
        - 이를 결과 리스트에 append
    - 최종적으로 리스트 안의 값들을 join
    - join 결과(문자열 타입) 반환

- LookAndSay.lookandsay : 입력값은 구하고자 하는 항(int 타입)
    - 여기서 입력항까지 반복하면 find_consecutive_groupby와 format_number를 차례대로 실행
    - 입력한 항의 개미수열 값(문자열타입)을 반환

- FindMiddle2Number.find_middle_nums : 입력값은 개미수열 값(문자열)
    - 가운데 두 자리 숫자를 구한 후 반환(int 타입)

- GetLookandsayMiddleNums.get_lookandsay_middle_nums : lookandsay와 find_middle_nums를 조합. 메인함수에 쓰기 위함

### 함수 구조 이유 설명
lookandsay(find_consecutive_groupby + format_number) -> get_lookandsay_middle_nums(lookandsay + find_middle_nums) -> 최종 메인 구조로 설계한 이유
- 우선 lookandsay로 합치지 않으면 최종 메인에 for문으로 처리를 해야함.
- 이를 방지하고자 1차적으로 lookandsay 함수를 만드는 것으로 설계
- get_lookandsay_middle_nums로 합친 이유 : 입력이 범위를 벗어났을 때 ValueError를 일으키기 위해서
- 마지막 main.py에서 try문으로 최종 에러처리
